# 编制方法与口径说明

本文件解释 vix.py 的算法来源、与官方方案的差异、数据源取舍，以及已知局限。
**任何引用本工具数值的场合，都应同时说明这些口径差异。**

## 二、算法：方差互换法（model-free variance）

与 CBOE VIX 同源，上交所《上证50ETF波动率指数编制方案》采用同一框架。

### 2.1 单一期限方差

```
σ² = (2/T) · e^(RT) · Σᵢ (ΔKᵢ / Kᵢ²) · Q(Kᵢ)  −  (1/T) · (F/K₀ − 1)²
```

- `T` 到期时间（年）
- `R` 无风险利率
- `F` 远期指数水平，由 call-put parity 推定：`F = K* + e^(RT)·(C(K*) − P(K*))`，其中 `K*` 取 `|C − P|` 最小的行权价
- `K₀` 不超过 `F` 的最大行权价
- `Q(Kᵢ)` 虚值期权价格：`K < K₀` 取认沽、`K = K₀` 取认购认沽均值、`K > K₀` 取认购
- `ΔKᵢ` 相邻行权价间距：中间取 `(Kᵢ₊₁ − Kᵢ₋₁)/2`，两端取相邻差

只使用**虚值期权**是关键——平值与实值期权价格含大量内在价值，会污染方差估计。

### 2.2 合成 30 天

```
VIX² = [ T₁σ₁²·(N·T₂ − 30)/(N·T₂ − N·T₁) + T₂σ₂²·(30 − N·T₁)/(N·T₂ − N·T₁) ] · N/30
```

`N = 365`。取夹住 30 天的近月（T₁）与远月（T₂）做线性加权。

### 2.3 两条方案硬规则

1. **7 天规则**：剔除剩余期限 ≤ 7 天的合约。临近到期时期权价格对时间极度敏感，方差估计会剧烈失真。
2. **近月 > 30 天时直取近月**（编制方案注 3）：若剔除后最近月份剩余期限已超过 30 天，则不做插值，直接 `VIX = 近月波动率 × 100`。

> 第 2 条在实战中出现频率很高。例如到期日为当月第四个星期三、而当月剩余不足 7 天时，近月会自动滚到下一个月份。

## 三、与官方方案的口径差异（重要）

| 项目 | 官方编制方案 | 本工具 | 影响方向 |
|---|---|---|---|
| 期权价格 | 按成交情况从买卖价推算 | 上交所披露**收盘价**（无成交用结算价） | 收盘价可能偏旧，个别合约偏差较大 |
| 无风险利率 | 对应期限 SHIBOR 插值 | 固定 1.80%/年（`--rate` 可覆盖） | 短端利率波动影响很小（T 短、只进指数项） |
| 行权价覆盖不足 | 用 BS 公式补虚拟行权价 | 不补，直接用现有行权价序列 | **主要偏差来源**，深度虚值端覆盖不足时低估 |
| 摘牌合约 | — | 按 `DELISTFLAG` 剔除 | 无 |
| 节假日顺延 | 到期日顺延处理 | 采用官方返回的 `EXPIRE_DATE` | 无（直接用交易所给的精确到期日） |

**量级参照**：各开源复现项目的自评——`nkuguanrui/ivx` 称与官方相似度 98.3%；`coolgan/calculate_ivix` 称「趋势一致、数值有差异」。
**本工具未做历史回溯校验**（上交所接口只提供当日合约快照，无法回溯），当前可信度依据是**横向交叉验证**，见第五节。

### 深交所方案的由来与字段验证方法

深交所官方接口只给合约清单、不给价格，因此采用「**深交所出元数据 + 新浪出价格**」的组合。

**关键风险**：新浪返回的是一个 51 字段的裸数组，没有字段名。**必须确定哪个下标是收盘价**，否则会静默算错。

**验证方法**（可复现，改动前请重做）：

1. 从上交所官方接口取 10 月合约（避开临近到期的 9 月合约，其流动性异常）
2. 用新浪批量查同样这批合约
3. 对每个候选字段，统计「与官方 `SECURITY_CLOSEPX` 完全相等的比例」与「平均绝对差」

实测结果（118 个样本）：

| 字段下标 | 完全等于官方收盘 | 平均绝对差 |
|---|---|---|
| [1] | 38 / 118 | 0.00203 |
| **[2]** | **118 / 118** | **0.00000** |
| [3] | 25 / 118 | 0.00185 |
| [8] | 2 / 118 | 0.03119 |
| [22] | 38 / 118 | 0.00203 |
| [44] | 1 / 118 | 0.03054 |

**结论：字段 `[2]` 是收盘价，118 个样本零误差。** 字段 `[1]` 和 `[22]` 数值相同、也接近，容易误判——**必须用批量统计而不是抽样目测来定字段**。抽样时曾误判为 `[1]`（恰好某只合约的 `[1]` 等于结算价，造成巧合）。

> 注意：新浪的**股票**行情（如 `sz159915`）字段布局与期权不同——股票是 `[1]`=今开 `[2]`=昨收 `[3]`=现价，期权的 `[2]` 才是收盘价。两者不可混用同一套下标。

> 东财弃用原因值得记录：其接口数据最全（含 5 品种 694 合约、字段丰富），但**抗限流能力差**。连续分页拉取后 IP 会被临时封禁，连 curl 都返回 000。上交所官方接口无此问题，且数据更具权威性——这是本项目最终选择官方源的决定性原因。

## 六、已实现波动率与 VRP 的定义

- **RV20**：标的近 20 个交易日对数收益率标准差 × **√当年实际交易日数**（年化，%）
- **VRP** = VIX − RV20
  - `> 0`：隐含波动率高于实际波动 → 期权**偏贵**，卖方策略有溢价可收，也意味着市场在买保险
  - `< 0`：期权**偏便宜**，较少见，通常出现在恐慌急跌后

### 年化因子必须用当年实际交易日数

**不能用美股惯例的 252。** A 股一年的交易日数不同——**2026 年是 242 天**。

用 252 会把 RV 系统性**高估约 2%**（√(252/242) = 1.0200），VRP 相应被低估同样的幅度。

修正前后对比（2026-09-18，同一次计算）：

| 品种 | VIX | RV（用 252） | RV（用 242） | VRP（252） | VRP（242） |
|---|---|---|---|---|---|
| 上证50ETF | 14.28 | 9.63 | 9.44 | +4.65 | **+4.85** |
| 沪深300ETF | 16.44 | 10.33 | 10.12 | +6.11 | **+6.32** |
| 中证500ETF | 23.97 | 18.85 | 18.47 | +5.12 | **+5.49** |
| 创业板ETF | 29.10 | 24.35 | 23.86 | +4.75 | **+5.24** |
| 科创50ETF | 36.08 | 33.38 | 32.71 | +2.70 | **+3.36** |

**代码位置**：`vix.py` 顶部的常量 `TRADING_DAYS_PER_YEAR`（当前 242）。**每年年底必须更新**——否则次年全年的 RV 与 VRP 都会有约 2% 的偏差。

### 一个更小的口径差异：VIX 的日历日折算

VIX 的期限 T 按**日历日 / 365** 折算（CBOE 的约定，theta 也按日历日衰减），而 RV 的年化基于交易日。两者都是「年化波动率」，**原则上可直接比较，不存在系统性偏差**。

唯一的细微差异来自：当某个月份「期限内交易日占比」高于全年占比（242/365 = 66.3%）时，VIX 会略高于交易日口径的年化值——典型情况下约 2–3%。这是 CBOE 方法的固有特性，所有同方法计算的 VIX 都有，**实践中忽略即可**。

## 七、已知局限（引用数值时必须一并说明）

1. **无历史序列**：上交所接口只返回当日快照。历史 VIX 需通过每日运行 `calc --all --save` 自行积累（落盘于 `data/vix_history.csv`）。在积累足够样本前，**任何「历史分位」结论都不可靠**。
2. **非官方指数**：本工具输出与已停发的官方 iVIX 存在系统性口径差异，不可与历史 iVIX 序列直接拼接比较。
3. **覆盖范围**：上交所 5 个 ETF 期权品种 + 深交所创业板ETF期权（159915），共 6 个。**不含**深交所其余 3 个（沪深300ETF、中证500ETF 与已覆盖品种指数重复；深证100ETF 冷门）与中金所 3 个股指期权（沪深300、中证1000、上证50）——后者需另接中金所接口。
4. **深交所品种的额外不确定性**：其价格来自新浪而非官方，虽然字段已用 118 个样本校验过零误差，但仍是第三方源，存在单点失效风险。
5. **创业板 / 中证500 / 科创50 没有长期历史参照**，分位无法给出。已穷尽排查（2026-09-18），结论如下：

| 可能的来源 | 排查结果 |
|---|---|
| 华创金工 HCVIX | 仅做**上证50 与 沪深300** 两个品种（页面明确说明），无其余三个 |
| 清华五道口 CIMV | 基于中金所沪深300股指期权，**数据止于 2023-03-31，已停更**，且每月才更新 |
| 期货日报 / 99期货 | 每日公布 12 个品种的**加权隐含波动率**（含创业板、科创50），但**只有当日快照，无历史序列** |
| 信达证券 China-VIX50 | 未见公开数据接口 |
| **自算回补** | **技术不可行**——算历史某日的 VIX 必须有该日的近月与次近月合约，而这些合约**已摘牌**；实测东财的搜索接口与 K 线接口**都查不到已摘牌合约**（见下） |

**自算回补为何不可行（实测记录）**：

1. 东财单个合约的历史 K 线**可得**（如 `secid=10.10010971` 返回 156 条日线），但只覆盖**该合约的存续期**
2. 要算 2026-05-15 的 VIX，需要 5 月（近月）+ 6 月（次近月）合约 —— 两者均已摘牌
3. 已摘牌合约的代码无法获取：东财搜索接口 `searchapi.eastmoney.com` 查「50ETF购6月」**返回 0 条**；按代码段推测的 secid（如 `12.90006900`）**返回无数据**
4. 因此**能回补的窗口极窄**。精确推算（2026-09-18）：算 D 日的 VIX 需要 D 时的近月与次近月合约，而当前挂牌合约中**10 月合约最早于 2026-08-27 挂牌**（9 月合约虽早在 1 月挂牌，但需次近月配合）。故可回补区间约为 **2026-08-27 ~ 09-18，仅约 16 个交易日**。

   **但即便这 16 天也拿不到——东财限流实测**：

   | 测试 | 结果 |
   |---|---|
   | 间隔 1.5 秒连查 | **第 4 个请求即被封**（`RemoteDisconnected`） |
   | 被封后等 90 秒重试 | 仍被封 |
   | 被封后等 4 分钟，间隔 25 秒连查 6 个 | **6 个全部失败**（封禁未解除） |
   | 数据正确性 | 封禁前成功取到的合约，末值与上交所官方收盘价完全一致（如 50ETF购9月2650 = 0.3291）——**数据是准的，纯粹拿不到** |

   回补 5 个品种需约 250 个合约，按「每 3–4 个封一次、每次恢复数十分钟」推算需数小时以上，**不可行**。

**唯一可行路径**：逐日积累自算序列（定时任务已配置）。或用**标的已实现波动率**（腾讯日线，可回溯）做长期波动水平的参照——**但那是 RV 不是 IV，口径不同，不可混淆**（见下条）。

6. **已实现波动率（RV）分位：口径必须标清楚**。为解决「创业板/中证500/科创50 没有 IV 历史」的空白，`percentile` 命令追加了 RV 分位（20 日已实现波动率，腾讯日线近 3 年 781 个交易日，全部品种覆盖）。

   | 口径 | 含义 | 方向 | 覆盖 |
   |---|---|---|---|
   | **VIX 分位** | 期权**隐含**波动率的历史位置 | 向前看（预期） | 仅 50ETF / 300ETF |
   | **波动水平** | 标的**已实现**波动率的历史位置 | 回头看（事实） | 全部品种 |

   **两者绝不可混称。** RV 分位能说明「当前波动水平在历史上算高还是低」，但**不能叫「VIX 分位」**。
   页面与终端输出都带了口径标签，改动时不要省掉。

   **数据源限制**：腾讯日线单次最多约 800 条（实测 800 返回 801 条；请求 2500 返回空），故 RV 分位窗口为「近 3 年」而非全历史。如需更长，可用 `param={code},day,起始日,结束日,320,qfq` 分段取（实测可行）。
4. **收盘后数据**：价格为收盘价，盘中运行得到的是上一交易日数据。上交所披露的 `TIMESAVE` 字段标明了数据日期。
5. **未补虚拟行权价**：当某月份行权价覆盖过窄（虚值端断档）时，方差积分会低估波动率。`term` 命令输出的 `行权价数` 可用于判断（低于 8 个需警惕）。
6. **节假日顺延未处理**：直接使用交易所返回的 `EXPIRE_DATE`，已规避该问题；但若要自行推算到期日，需注意第四个星期三遇节假日顺延的规则。
7. **计算基准日必须用数据日期，不能用系统日期**（这是踩过的坑，见下节）。
8. **上交所日终数据更新有延迟**：实测 2026-09-18 21:17 时接口仍返回 09-17 快照（标的收盘 2.958，而腾讯当日行情已是 2.975）；**21:27 再查已更新为 09-18**（标的收盘 2.975，VIX 14.97→14.28）。初步判断发布窗口在 21:00–21:30 之间，**但仅两次观测，未充分验证，不要当作确定规律**。

### 数据迟滞的自动提示机制

避免用户看到非当日数据却不知道原因。脚本会比较两个日期：

| 判据 | 含义 | 是否解释 |
|---|---|---|
| 数据日期 == 市场最后交易日 | 数据是最新的（含非交易日复用上一交易日数据） | **不解释**，属正常 |
| 数据日期 < 市场最后交易日 | 交易日已过，但数据源还没更新 | **自动解释** |

- 「市场最后交易日」取自腾讯行情 `qt.gtimg.cn` 的时间戳字段（每 10 分钟缓存，避免多品种重复请求）
- 提示同时出现在 `vix.py` 终端输出与 `vix_report.html` 页面顶部（红色警示条）
- 文案明确说明是「上交所日终数据发布延迟」，并提示次日自动重跑会补齐

> 这是使用方提出的需求：「如果不是今天的（假设今天是交易日），麻烦解释为什么；今天不是交易日用上一交易日数据就很正常，不用解释。」逻辑即上表。

## 八、两个已修复的坑（维护时务必留意）

### 坑 1：用系统日期当计算基准，导致同一份数据算出不同结果

**现象**：9/17 晚算出 50ETF VIX = 14.97 并入库；9/18 晚对**同一份 9/17 数据**（标的收盘仍是 2.958）重算，却得到 15.16。且因为数据日期字段没变，去重逻辑判定「已存在」而拒绝保存，数值漂移被静默吞掉。

**根因**：剩余期限 `T` 是用系统当前日期算的。9/18 跑的时候，10 月合约的剩余天数被算成 40 天（而非 41 天），`T` 变了，`σ²` 和插值结果跟着变。**期权价格是 9/17 的，分母却用了 9/18 的时间。**

**修复**：基准日改用 `TIMESAVE`（交易所披露的数据日期），而不是 `date.today()`。修复后重算，五个品种精确回到 14.97 / 17.22 / 25.99 / 37.71 / 37.75，与已入库记录逐位一致。

**教训**：凡是「市场数据 + 时间衰减」的计算，时间基准必须锚定数据自身的时间戳，不能锚定运行时刻。

### 坑 2：数据日期字段滞后，会误伤去重

`TIMESAVE` 反映的是**数据所属交易日**，而交易所发布时间比收盘晚得多。定时任务若在数据发布前运行，拿到的是上一交易日快照——此时去重会正确跳过，但**当天数据就漏了**。

**应对**：定时任务定在**次日早上**（工作日 08:35），而非收盘后。代价是页面显示的是前一交易日的 VIX；收益是数据完整、不会空转。波动率本身就是收盘后指标，晚一晚上不影响判断。

> 想更及时可以再验证发布时间窗（可能需要 21:00 之后），但不要在没验证的情况下假设「收盘后就有」。

### 坑 3：VIX 与 RV 来自不同数据源，时间基准会错位

**现象**：9/18 晚上跑，VIX 仍是 9/17 的（上交所滞后），但 20 日已实现波动率变成了 9/18 的（腾讯及时）。两个数来自不同交易日相减得 VRP，结果失真——实测 RV 从 9.34 漂到 9.79，VRP 从 +5.64 变 +5.19。

**根因**：`realized_vol()` 取的是腾讯日线的**最新 20 天**，没有锚定 VIX 的数据日期。

**修复**：给 `realized_vol()` 加 `end_date` 参数，只取该日期（含）之前的行情；调用时传入 `trade_date`。修复后 RV 回到 9.40 系，与首次数值吻合。

> 残余差异说明：腾讯用的是前复权（qfq）数据，标的分红后历史价格会被重算，因此 9.34 与 9.40 这种千分之几的差异属正常，不影响 VRP 的符号与量级判断。

**通用教训**：多数据源拼装的指标，**所有分量必须锚定同一个基准日**。否则数据源的更新速度差异会悄悄污染衍生指标，且这种污染不会报错。

| ≥ 40 | 极度恐慌 | `#ef4444` 深红 |

代码位置：`vix.py` 的 `sentiment()` 与 `build_html.py` 的 `vix_color()`，**两处必须同步修改**，否则页面颜色与文字标签会错位。

### 为什么不是美股那套

初版照搬了美股 VIX 的习惯（12 以下极度平静、12–16 平静、16–20 中性、20–25 偏谨慎……），**这是错的**。

官方中国波指 iVIX（代码 000188）停发前（2016-08 ~ 2018-02）的实测统计：

- 均值 **15.19**
- 全区间 **11.15 ~ 21.41**
- **80% 的时间落在 13.07 ~ 17.61**

A 股波动本身比美股大，**13–18 才是 A 股的常态**。用美股阈值会把 A 股最常见的区间误标成「平静」，把真实常态推向「中性」一侧。

### 2015 年股灾实测参照

| 时点 | iVIX |
|---|---|
| 2015-04 牛市顶部 | 47 |
| 2015-06 泡沫顶部 | 49 |
| 2015-07-08 暴跌后首次反弹 | 60 |
| 2015-08-26 阶段最低点 | 65+ |
| 2016-02 底部 | 38 |

对应关系：**市场转折点（顶或底）时波指会显著抬高，40 以上基本就是极端状态。**

### 数据来源与可信度

| 数据 | 来源 | 可信度 |
|---|---|---|
| 均值 15.19 / 区间 11.15–21.41 / 80% 在 13.07–17.61 | optbbs 论坛帖（转述该期间统计） | 中 —— 数值具体但属论坛转述 |
| 2015 年各时点数值 | 雪球个人分析（xueqiu.com/7969186433/145879106） | 中 —— 有具体日期，未交叉验证 |
| 中国波指历史序列 | 华泰证券研报 PDF | 高 |

**未做的验证**：上述统计没有找到官方原始数据源（上交所未公开历史序列）。若日后获取到更长序列，应重新校准。

### 局限与后续

1. **实证数据是 2015–2018 年的**，而 2026 年市场结构已显著变化——期权品种从 1 个增至 6 个、参与者结构与标的不同。这套阈值是「更合理的参考」，不是精确标准。
2. **最终解法是用本 skill 自己的历史序列算分位**。`history` 命令已实现分位计算，但需要 3–6 个月（约 60–120 个交易日）的样本量才有意义。在样本不足 20 条时它会主动拒绝输出分位结论。
3. 积累足够后，可考虑把绝对阈值改为**滚动分位**（如「当前处于近一年 30% 分位」），那比固定阈值更能适应市场结构变化。

## 十、历史回补（backfill.py / recompute.py）

### 10.1 为什么要回补

中证500、科创50、创业板**没有第三方公开的 IV 历史序列**：

| 候选源 | 排查结果 |
|---|---|
| 华创 HCVIX | 只做上证50 与沪深300，明确不含其余品种 |
| 清华五道口 CIMV | 基于中金所沪深300股指期权，数据止于 2023-03-31，已停更 |
| 期货日报「期权市场」日报 | 每日公布 12 个品种加权 IV（含这三个），但文章格式不统一、非每日发布、且是**加权 IV** 而非方差互换 VIX |
| 中证指数公司 | 只有「波动率加权指数」（000803/000804，选低波动股加权），**不是波动率指数**，勿混淆 |
| 深交所 000993 | 实为「全指信息」指数；网络流传的「000993 = 中证500波指」是**错误信息** |
| 官方 iVIX 000188 | 2018-02 停发；腾讯有代码但价格为 0，上交所 yunhq 返回 296 个历史日但 kline 为空 |

因此只能自己从**原始期权日线**重算。

### 10.2 唯一可行的数据源：东财，但限流严苛

`push2his.eastmoney.com/api/qt/stock/kline/get`（secid 格式：上交所期权 `10.{合约代码}`）。

**实测限流特征**（2026-09-18）：

| 观测 | 结果 |
|---|---|
| 单次请求 | 成功 |
| 间隔 1.5s 连发 15 个 | **全部成功**（约 22 秒内） |
| 紧接着继续请求 | **全部失败**（HTTP 000 / RemoteDisconnected） |
| 静默 90s / 4min 后重试 | 仍失败 |
| 数字前缀镜像域名（`1.` `2.` `35.` 等） | 与主域名**共享同一套风控**，封禁时一并失效 |
| 完整浏览器 headers（Accept / Sec-Fetch / gzip） | 无改善 |
| 移动端 UA | 无改善 |

**结论**：这是**按时间窗口的配额限流**——窗口内允许约 15 个请求，超出即封禁，且封禁时长随累计请求量延长。不存在稳定的「安全速率」。

**因此**：回补只能以「一批 → 长静默 → 再一批」的节奏推进，`backfill.py` 的内置退避即为此设计（连续失败 N 次 → 休眠，逐级翻倍，上限 900s）。

### 10.3 覆盖窗口的硬限制

回补**只能覆盖最近 3–4 周**，原因是 VIX 需要「当日的近月 + 次近月」合约，而**已摘牌合约查不到**：

- 东财搜索接口查「50ETF购6月」返回 0 条
- 按代码段推测的 secid 返回无数据
- 交易所官方接口只提供当前挂牌合约，不提供历史合约清单

以 2026-09-18 为例，可回补窗口约 **2026-08-19 ~ 09-18**（22 个交易日），需要 9 月、10 月、12 月三组到期月的合约。

### 10.4 请求数优化

`backfill.py` 按 `STRIKE_BAND = 0.12`（行权价在标的 ±12% 内）过滤合约。
依据：VIX 积分中行权价 K 的权重 ∝ 1/K²，深度虚值合约贡献极小。

效果：上交所 272 → **130** 个，加深交所合计 236 个（未过滤前 378 个）。

代价：极端行情下会轻微低估尾部风险。回补结果中标注了这一点。

### 10.5 已排除的数据源（勿重复调研）

| 源 | 结论 |
|---|---|
| 新浪 `hq.sinajs.cn` | 有期权**实时**行情（含成交额字段 42），**无历史 K 线接口**（OptionService 系列全部 Service not found） |
| 腾讯 `qt.gtimg.cn` / `ifzq.gtimg.cn` | **不认期权代码**（`sh10011256` 返回空） |
| 网易 `quotes.money.163.com/service/chddata.html` | 接口整体 502（含普通 ETF），不可用 |
| 同花顺 `d.10jqka.com.cn/v6/line/` | 对 ETF 正常，对期权**全部 404**（多种前缀均试） |
| 雪球 `stock.xueqiu.com/v5/stock/chart/kline.json` | 需登录 token，匿名请求返回 error_code 400016 |
| 上交所 `yunhq.sse.com.cn:32041/v1/sh1/dayk/` | 对**指数/ETF 有效**（可作标的日线源），对**期权合约 404** |
| mootdx（通达信 TCP 7709） | `stocks()` 可取 27933 个证券（连接正常），但 `bars()` 返回 0 条；期权属**扩展行情**，`market='ext'` 服务器在本机环境连接超时 |
| optbbs.com QVIX | 本机不可达（HTTP 000） |

### 10.6 使用方式

```bash
python3 backfill.py --status                    # 看进度（断点续传，可随时中断重跑）
python3 backfill.py --market sse --limit 20     # 回补一批
python3 recompute.py --save                     # 用已回补数据重算历史 VIX
```

回补结果落盘 `data/history_raw/{market}_{合约代码}.json`；重算结果写 `data/vix_history_backfill.csv`。

`recompute.py` 的算法与 `vix.py` **完全一致**（同一套 `term_variance` / `combine_30d`），因此重算序列与实时计算的数值可直接拼接。
